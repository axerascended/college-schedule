# Материалы для пояснительной записки

## Сравнение «до / после»

| Критерий | Excel / бумага | Данная система |
|----------|----------------|----------------|
| Конфликты расписания | Проверка вручную | Автоматически при сохранении |
| Доступ студентов | Файл в мессенджере | Веб-кабинет 24/7 |
| Версии расписания | Несколько файлов | Единая БД + публикация периода |
| Мобильный просмотр | Неудобно | Адаптивная вёрстка Bootstrap |

## ER-модель (кратко)

- **User** — роли admin / student / teacher; студент привязан к **Group**.
- **SchedulePeriod** — семестр с датами и флагом `is_published`.
- **ScheduleEntry** — занятие: группа, предмет, преподаватель, аудитория, слот времени, тип недели (every/odd/even).
- **TimeSlot** — день недели (0–5) и номер пары.

## Алгоритм проверки конфликтов

1. Выбрать все занятия с тем же `time_slot_id`, у которых периоды дат пересекаются.
2. Отфильтровать по совместимости `week_type` (`every` пересекается с любым типом).
3. Для каждой кандидатной записи проверить совпадение `group_id`, `teacher_id` или `room_id`.
4. Вернуть список сообщений для отображения пользователю.

Реализация: `app/services/schedule_conflict_service.py`.

## Скриншоты для отчёта

Рекомендуется сделать снимки экрана:

1. Страница входа (`/login`).
2. Сетка расписания администратора (`/admin/schedule`).
3. Форма занятия с сообщением о конфликте.
4. Справочник групп.
5. Публикация периода (`/admin/periods`).
6. Расписание студента на телефоне (эмулятор DevTools).

## Запуск для демонстрации

```bash
py -3 -m pip install -r requirements.txt
py -3 -m alembic upgrade head
py -3 -m app.scripts.seed
py -3 -m uvicorn app.main:app --reload
```

Учётные записи см. [README.md](../README.md).

## Перспективы развития (заключение)

- Полуавтоматическая генерация расписания (жадный алгоритм, OR-Tools).
- Импорт из Excel.
- Роль преподавателя с просмотром личной нагрузки.
- PostgreSQL и развёртывание на сервере колледжа.
